# 转入（Transfers）PRD

> 状态：2026-11-13 确认。这是后续实现的产品需求，本文档不表示功能已经做出。
> 英文名 Transfers。iPhone 界面叫「转入」。同步按钮叫「同步到 Mac」。

把 Hex Mobile 收成一个可转发的落点。别的 App 把文字、图片或文件交给它，用户点「同步到 Mac」之后，Mac 上的 Hex 在「转入」里收下。听写、键盘和词表同步保持原样。

实现时仍遵守 [PLAN.md](PLAN.md) 的硬约束：免费 Personal Team 能签名、应用自己不发网络请求、Hex 只通过 CLI 读写、不直接改 Hex 的设置文件。本功能有一条例外，写在下面的「已经定下的取舍」和「隐私」里。

## 已经定下的取舍

1. **新加一个分享扩展。** 这是第四个 bundle id（App、小组件、键盘之外）。免费 Personal Team 有 App ID 数量限制；签不出来时需要付费开发者账号，不拿掉键盘或小组件来腾位置。
2. **继续不用 App Group，也不加 iCloud entitlement。** 点「同步到 Mac」之前，内容已经在用户选过的 iCloud Drive `Hex Mobile` 文件夹里，状态是待同步。Mac 只导入点过同步的条目。分享扩展和主应用各自保存这份文件夹的安全作用域书签。
3. **Hex 的「转入」放在 Labs 开关后面，默认关闭，只有 macOS。** 开关打开后，侧栏在 History 后面出现这一页。Linux 和 Windows 不出现。

## 问题

现在 Mobile Sync 只搬运词表、听写语言和模式。文字、图片和文件没有一条从任意 App 到 Mac 版 Hex 的路。iCloud 文件夹和 Mac 上的 `mac/hex-mobile-sync.sh` 已经是两端之间的管道，这一版沿用它，不另开网络。

使用者是同一 Apple ID 下、已经选过同步文件夹的那台 iPhone 和那台 Mac。

## 一次转入里有什么

一次分享是一条转入，最多 10 个附件。单个附件上限 100 MB，一条上限 200 MB。超出就停在分享页，不保存。

| 来源 | 这一版怎么收 |
|---|---|
| 纯文本 | 存成 UTF-8 的 `body.txt` |
| 链接 | 存成文字 |
| 富文本 | 只用对方提供的纯文本；没有纯文本就不收这一项 |
| 图片 | 保留原始文件和 UTI。Live Photo 只收对方给出的那张图 |
| 其它文件 | 保留原文件名 |
| 文件夹、软件包 | 拒绝 |

分享扩展用文件对拷，不把整个附件读进内存。两端都还看不到同步文件夹时，这次分享取消，不另存一份。

来源 App 的名字不可靠，不作为字段承诺。

## 路径

1. **分享到 Hex Mobile。** 分享页显示摘要、可改的一行标题，以及可选备注（最多 200 字）。主按钮是「同步到 Mac」，次按钮是「先收下」。还没选过文件夹时，先在这张表里用文件选择器选中同一个 `Hex Mobile` 文件夹，书签存在扩展自己的容器里。
2. **iPhone 上的转入。** 主应用新的「转入」页列出待同步和已点同步的条目。待同步可以再点「同步到 Mac」，也可以删除。
3. **用其它 App 打开。** 文件或图片经系统交给主应用时，同样变成一条待同步，不直接送上 Mac。
4. **Mac 导入。** launchd 脚本看到已排队、尚无回执、并且 iCloud 已下完整的条目，且 Hex 正在运行时，用 `hex` CLI 导入。Hex 打开时也会再扫一遍。Hex 没在运行就留到下一次。占位文件先跳过。脚本不写 Hex 的设置文件，也不碰 `hex-mobile-sync.json` 和 `pending-vocabulary.json`。
5. **Hex 里打开。** Labs 打开后，侧栏在 History 后面出现「转入」，列表加详情，版式与 History 相同。窗口不在这个页面时，给一条本机通知。不用 APNs。
6. **回执。** 导入成功后 Mac 写下回执。同一 id 再导入一次是空操作，仍然补回执。iPhone 下次回到前台，把标题、时间和状态留在本机，并删掉 iCloud 里的那份文件。

## iPhone 界面

主应用增加第五个 Tab「转入」。一行显示种类、标题、时间和状态：

| 状态 | 含义 | 用户能做的 |
|---|---|---|
| 待同步 | 已在同步文件夹，Mac 还不会收 | 再点「同步到 Mac」，或删除 |
| 已排队 | 已点同步，Mac 尚未写下回执 | 删除。删除后 Mac 不应再收到 |
| 已到达 Mac | 已看到回执 | 只留标题、时间和状态。删除只去掉这条本机摘要 |

删除待同步或已排队的条目时，删掉 iCloud 里对应的目录。分享页和 App 里用同一套文案：英文为主，意大利文目录按现有 String Catalog 的做法补上。简体中文不是这个 App 的界面语言。

## Mac 界面

只在 macOS、并且 Labs 的「转入」打开时出现。左侧列表，右侧详情。

- 列表一行：种类、标题、时间。多个附件时能看出是多项。
- 详情：文字可以选中和复制；图片可以预览并复制；文件和图片都可以在 Finder 里显示。备注显示在详情里。
- 用户点复制之前，不改系统剪贴板，也不写进听写历史。
- 删除只删这台 Mac 上的副本，不回头删除 iPhone 上的摘要。
- 空列表有空状态。同步文件夹不存在时，页面就是空的，不当成错误。

Hex 的文案走现有的界面语言，包括简体中文。

## 同步文件夹

新目录与现有同步文件分开：

```
Hex Mobile/transfers/<uuid>/
  manifest.json
  body.txt                 # 有文字时
  <original filenames>     # 图片和其它文件
  receipt.json             # 仅 Mac 导入成功之后
```

`manifest.json` 由 iPhone 写，`schema_version` 为 1：

- `id`：UUID，与目录名相同
- `status`：`held`（待同步）或 `queued`（已点同步）
- `created_at`：UTC 时间
- `title`：一行标题
- `note`：备注，可空
- `attachments`：文件名、UTI、字节数、种类（`text`、`image`、`file`）

未知字段忽略。缺 `schema_version` 或版本更新时，Mac 跳过该条并留下日志，不导入半份。

`receipt.json` 由 Mac 脚本在 CLI 成功之后原子写入，`schema_version` 为 1，包含同一个 `id`、送达时间和 Hex 版本。脚本不改写 `manifest.json`。

Mac 上的正式副本在 Hex 自己的 Application Support 里，权限与听写历史一样只给所有者。保留到用户删除，这一版不做自动过期。

诊断日志只记 id、种类、字节数和状态，不记正文，也不记文件内容。

## 隐私

这条管道是现有「听写不出设备」之外的明确例外：只有用户转发、并点了「同步到 Mac」的内容，会经该用户的 iCloud Drive 到达这台 Mac。点同步之前的「待同步」已经在同一个文件夹里。应用自己仍不发请求。回执到达后，同步文件夹里的该条文件删除。词表、模式、听写历史的现有规则不变，Hex 的 AI 后处理设置仍然不导出。

## 怎样算做完

在真机上：

- 从备忘录、照片和文件 App 各转发一条文字、一张图片、一个普通文件。
- 停在待同步时，Mac 的「转入」列表是空的。
- 点「同步到 Mac」并且 Hex 开着，这一条出现在「转入」里。文字能复制，图片能预览，文件能在 Finder 里打开。
- iPhone 上变成「已到达 Mac」，iCloud 里的该条文件消失。
- 同一条不出现第二次。
- 删掉 iPhone 上还没同步的条目后，Mac 收不到它。
- 听写、键盘、词表双向同步仍按原来的方式工作。

iOS 侧没有 CI。分享页、后台导入和 iCloud 占位文件要在真机与一台开着 Hex 的 Mac 上看。Mac 侧的导入幂等可以有单元测试。

## 这一版不做

- iPhone 收回 Mac 上的文件
- 同步后自动用某个 Mac App 打开
- 识图、转写，或把转入交给 agent
- 改完再同步的正文编辑器
- 两端互相删除
- 推送通知
- 把来源 App 的名字当作可靠字段
